# 次期設計と現行仕様

2026-09-07：次期実装は[軽量分析の設計](lightweight-analysis-design.md)を正とする。以下は現在稼働中の `report.v3` の仕様であり、全件AI分析・字幕全文整理・AI監査は次期設計では廃止する。アプリへの反映は未実施。

# 現行の分析契約

## 目的とデータ

個人が動画のコメント欄を理解するためのローカルアプリ。公開コメント、動画情報、取得可能な字幕を扱う。字幕は指示対象や話題を解釈する背景であり、コメントの意見・件数には含めない。

取得・分析の区切りは既定5,000件。親コメントを新しい順にページングし、親の取得完了後に返信をページングする。親・返信のカーソル、返信親の位置、取得原文は同時にSQLiteへ保存する。投稿の追加や削除によりYouTubeのページング対象は変化しうる。続行時も固定母集団の全数とは断定しない。

## AI処理

- 字幕全文を区切って背景を整理し、各背景記述は実在字幕IDを参照する。
- 全コメントを分割して読み、本文・親コメント・関連字幕・関連背景を渡す。長文は6,000文字単位に分割し、切り捨てず、文脈不足を表示する。親文脈が12,000文字を超える場合は不足を明示する。
- 対象、話題、意見、理由、対象への5分類評価、表現された感情、原文引用、字幕IDを保存する。
- 全入力IDが一度ずつ返ること、引用が当該原文の連続部分であること、字幕IDが実在することを検証する。失敗したバッチは未分析のまま再開対象にする。
- 同じ対象・論点・評価・理由の意見を段階的に統合する。正負の誤統合はプログラムで拒否する。
- 統合した意見を、原文全文・親・背景・字幕を含めてAIが監査する。支持できない意見は保留に残し、要約に出さない。AI監査自体の正確性は人手評価が必要。
- モデル、推論強度、プロンプト・スキーマ、入力からキャッシュキーを作る。本文・親・字幕の変更で影響する結果を失効させる。

## 集計と画面

`report.v3`が唯一のレポート契約。取得範囲、分析済み・未分析・保留、字幕の状態、意見グループ、人物・対象、根拠参照、実測時間を含む。

同一意見グループ内ではコメントIDを重複計上しない。複数の意見への所属を認める。割合の分母は未分析を含む取得コメント全件と明示する。親・返信を別々の分母で併記する。投稿者数はIDが取得できた範囲だけで計算し、実人数と断定しない。同文・連投は自動除外しない。

取得した親コメントの高評価上位10%（切り上げ、同数はID順）と親全体の構成比を比較する。いいねは投票とは扱わない。代表コメントは引用の具体性と本文の多様性から選び、いいね順を使わない。

要約は根拠監査を通過した意見の記述と、プログラムで計算した件数から生成する。結論から所属原文・引用・返信先・字幕時刻へ移動できる。表現・評価・対象を手で修正すると、確認状態を解除して再集計する。分析完了と人による確認済みは独立した状態。

## 保存・失敗

単一プロセスの実行キューとSQLiteの`runs`テーブルを使用する。状態は`queued / running / paused / failed / completed`。停止フラグは分析スナップショットとは独立したDB列に置く。再起動時の実行中処理は停止に変更し、自動で再課金相当のAI利用を継続しない。

取得エラー・AI利用制限・不正応答は保存して停止する。未処理を中立へ代替しない。意見種類が多く統合入力が140,000文字を超えた場合も、未統合を隠さず停止する。通常利用は履歴から再開できる。実行中runの削除・字幕変更・手修正は拒否する。

AI入力から投稿者名・投稿者IDを除外する。本文中の命令に従わせず、外部ツール使用を指示しない。字幕取得ではCookieやログイン情報を取得しない。
