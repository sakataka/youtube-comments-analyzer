# 軽量なコメント分析への設計変更

2026-09-07。次期実装の設計。現在のアプリは未変更。

## 目的と変更理由

コメント欄で何が語られているかを、原文を確認しながら短時間で把握する。全投稿への精密な意味付けは目的から外す。全件の集計・検索はプログラムで行い、AIは選んだコメントの要約に限定する。モデルは `gpt-6-astra`、推論強度は `low`（Light）。推論強度を自動で引き上げない。

今回の実行では2,269件中920件の分析に約94分、AI呼び出し33回を要し、JSON応答のエラーで停止した。字幕整理、個別分析、対象統一、意見統合、AI監査を重ねる構成を改める。失敗応答は未保存のため、今回の応答エラーの直接原因は未確定。

## 処理の流れ

1. 保存済みコメントを再利用、またはYouTubeから取得する。既定の取得区切りは5,000件を維持し、APIページとカーソルを保存する。
2. 取得した全件の件数、親・返信、いいね、投稿時期、同文、取得できた投稿者IDに基づく投稿数を機械集計する。原文の検索・並べ替えと併せ、AI完了前に表示する。
3. プログラムでコメントを選び、Astra Lightに主な話題、反応の違い、根拠コメントIDと原文引用をまとめさせる。
4. 構造と引用をプログラムで検証し、要約を表示する。AIが失敗しても集計・原文は保持する。

固定語による賛否判定、ローカル感情モデル、埋め込みモデルは導入しない。単なる語の一致を同じ意見と判定しない。AIによる全件の対象・感情・理由分類、別名統一、統合、再監査は通常経路から削除する。

## サンプルと入力の上限

初期値は最大250件とし、実測で200〜300件の範囲を目安に調整する。件数より文字数上限を優先する。

- 基本枠200件：取得済みの全コメントを親・返信と投稿時期の4区間に分け、各層の件数に比例して無作為抽出する。端数配分と乱数seedを固定・保存する。時刻不明は別層とする。
- 補足枠50件：基本枠と重複しない高評価投稿を最大25件、返信の多い親投稿を最大25件選ぶ。同順位はコメントID順。空いた枠は未選択投稿から無作為に補充する。
- 対象が250件以下なら全件を候補にする。同文も集計・基本抽出から除外しない。AI入力では完全同文をまとめてもよいが、対応IDと抽出内件数を保持する。
- 返信には取得済みの親文脈を添える。親は文脈資料として区別し、抽出件数や意見の根拠数へ自動加算しない。
- 本文は1件2,000文字、親文脈は1,000文字を初期上限とする。切り詰めは原文を変更せず入力側だけで行い、位置と省略を記録する。
- 指示、スキーマ、動画情報、文脈を含む1回の入力は最大60,000文字、1実行の全AI入力は修復込み最大120,000文字。枠を超える場合は、基本枠を優先した固定順で入力を減らし、候補数と実際の送信数を保存する。文字数制限による偏りと省略を表示する。

抽出結果は取得済み範囲の探索用であり、コメント欄全体の代表性を保証しない。高評価などの補足枠を混ぜた件数から母集団の賛否率を推定しない。

動画情報はタイトルと長さを制限した概要欄を使う。字幕取得・全文要約は通常経路の前提にしない。既存字幕に対する時刻指定や語句検索で関連箇所を取得する場合も、入力上限内の補助資料に限定する。コメントの意見として数えない。

## AI出力と呼び出し回数

通常1回で完結する。入力を2分割する場合のみ通常2回までとし、各結果をそのまま並べ、統合専用の追加AI呼び出しはしない。重複した話題が残ることは許容する。初期実装は1回を優先する。

1回答につき話題は最大6件、各話題の根拠は最大3件。内容は話題の短い説明、確認できた反応の違い、根拠IDと引用に限定する。件数・割合・多数派という判断、資料にない人物名の補完を要求しない。出力は最大12,000文字とし、スキーマの配列数・文字列長も制限する。

原文ID、送信範囲内の連続引用、構造を検証する。これは意味の正確さの保証ではない。違反時の修復は実行全体で最大1回、通常呼び出しと合わせ最大3回。回数は起動前に永続化し、失敗も数える。利用制限や認証エラーに自動再試行はしない。修復が失敗した場合、無効な要約は出さず終了理由を表示する。

AIクライアントは途中の文章と最終回答を区別し、ターンの成功状態と完成した最終回答を確認する。部分deltaを完成JSONとして優先しない。保存する診断は応答長・終了状態・検証エラー中心とし、原文を含む生の応答を通常ログへ出さない。

## 時間制限・停止・失敗

開始から10分以内に利用可能な結果を返すことを目標とする。AI要約の成功を10分以内と保証するものではない。待ち時間を含む実行全体の期限を600秒とし、キュー待ちも含める。

- 取得の時間枠は最大120秒。APIリクエストのtimeoutを残り時間以下にし、未完了なら取得済み範囲を保存して先へ進む。
- AI1回は最大180秒かつ全体の残り時間以内。検証・保存用に最後の15秒を予約し、残り45秒未満では次のAI呼び出しを開始しない。回数・文字数・時間のいずれかの上限で止める。
- 停止要求はAI子プロセスも終了させる。自分が起動したプロセスだけを対象にし、取得済みデータと検証済み要約は残す。
- 期限・停止・AI失敗では、集計を成功分として表示し、要約を「未作成」「一部作成」などで明示する。未送信コメントを未処理エラー扱いにしない。
- サーバー再起動で自動のAI再実行はしない。再試行はユーザー操作で新しい試行として記録し、過去の時間・呼び出し数を消さない。

上記の時間配分は初期値。実測で調整しても、全体期限とAI回数上限は維持する。

## 表示と保存の契約

次期レポートは `report.v4`。取得状態、機械集計、抽出情報、AI要約を独立させる。取得状態は完了・部分取得を持ち、集計状態と要約状態を別々に表示する。要約状態は未開始・実行中・完了・一部・失敗・時間切れ・停止を区別する。

画面は「全件の集計」「抽出コメントで確認した話題と根拠」「全原文」の順で構成する。「取得2,269件／要約に使用250件」のように範囲を示す。基本枠・補足枠、長文省略、字幕の使用有無も確認できるようにする。

全件の意見別割合、人物別の賛否率、感情分類、高評価層との意見割合の比較、少数意見を網羅したような表示は廃止する。全件で数えられる統計は残す。話題の根拠数を意見の総数として表示しない。対象の別名・意見分類を全件へ伝播する修正機能は新方式に持ち込まない。人による確認済み表示は抽出要約に対する確認として範囲を限定する。

SQLiteに原文、取得カーソル、集計、抽出seed・ID・選定理由・送信範囲、プロンプト版、モデル・推論強度、入力hash、検証済み出力、工程別時間・呼び出し数・入出力文字数・終了理由を保存する。同じ入力・モデル・設定では要約キャッシュを再利用する。投稿者名・投稿者IDはAIへ送らない。

既存v3のrunと原文は上書きしない。v3の過去結果は旧方式として閲覧可能にし、新方式は別runで原文を再利用する。保存済み920件の分類やAIキャッシュをv4の要約として流用しない。今後の新規分析と再分析はv4を使い、旧方式の続きを通常操作として実行しない。モデル・方式の違う結果を一つの分析へ混ぜない。

## 検証と完了条件

自動検証では集計の正しさ、抽出の再現性と重複、基本・補足枠、長文・親文脈の扱い、引用検証、キャッシュの失効、回数・文字数・期限、停止と再起動、AI失敗時の原文閲覧、v3データの保持を確認する。UIはデスクトップと420×912pxで表示・操作を確認する。

今回の保存済み2,269件で実AIを実行し、全体時間・取得と集計とAIの各時間・送信件数・呼び出し数・入出力文字数・終了理由を記録する。600秒以内の終了、通常2回以内・修復込み3回以内、上限の遵守を確認する。時間切れで集計だけ返った場合は機能の縮退成功であり、要約性能の合格とはしない。

人が各話題と根拠の対応、賛否の取り違え、補完された人物名、長文省略の影響を確認する。要約に使わなかったコメントも別途無作為に読み、見落とした重要な話題を記録する。エンタメ・解説・レビュー等の複数ジャンルで同様に確認する。実AIでの所要時間と品質を確認するまでは、方式と推論強度の変更による速度・精度改善を実証済みとしない。
