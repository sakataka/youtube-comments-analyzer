# 動作確認と復旧

`GET /api/health`が`report_schema: report.v3`を返すことを確認する。画面とAPIが食い違う場合は`bun run build`後に、このアプリのAPIサービスだけを再起動する。

- **キー未設定**：`.env`の`YOUTUBE_API_KEY`を設定し再起動。実URLをテスト用fixtureで自動代用しない。
- **字幕なし**：分析は継続できる。VTT・SRT・JSON3を画面から取り込むと背景を含めて再分析する。
- **Codex失敗・利用制限**：Codex CLIへのログインと利用状態を確認し、保存済みの続きから再開。AIの不正応答も未処理として保存される。
- **保留がある**：根拠のない対象や評価を確定していない。「判断保留の根拠を確認」から原文・監査理由を読み、必要なら修正する。
- **取得が途中**：区切りに達したら続行する。APIのページが無効になった場合は、新しい動画分析の詳細設定で保存データを使わない取得を選ぶ。
- **停止がすぐ終わらない**：進行中のAI呼び出しは最大10分まで待つ。サーバー再起動時も保存済みバッチを保持する。
- **E2Eがbind不可**：サンドボックスのloopback制約を確認する。E2Eサーバーは通常のDBとは独立した一時ディレクトリを使う。

DBは現行構造のみを使用する。切り替え前のDBは退避資料として扱い、アプリの現行DBへ戻して混在させない。
